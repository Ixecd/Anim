## 哲学根基

**Anim 的依赖管理不是关于"零依赖"，而是关于"依赖不拥有我们"。**

每条外部代码进入项目，必须能回答三个问题：

1. **它侵入核心逻辑吗？** — 如果它决定了 Anim 如何做类型检查、安全校验、IR 生成，它就不只是"依赖"，而是"共同决策者"
2. **它被限定在边界吗？** — 如果它只在 I/O 层、可观测性侧支、或序列化层，且失败时不影响主路径
3. **我们控制它的退出成本吗？** — 如果有一天需要替换它，代价是一条 trait 适配器还是整个架构重构？

---

## 三级分级标准

### Level 0 — 禁止：逻辑侵入性依赖

接管了本应由 Anim 自己实现的核心路径。

**当前 Anim 状态：** 无 Level 0 依赖（代码零行）。

**未来候选（需单独论证）：**
- 任何完整的感受信号处理引擎（Anim 必须自己实现四层 IR 变换）
- 任何类型系统的第三方完整实现（Anim 的类型系统是感受专用的——没有现成库）

---

### Level 1 — 受限：标准协议库 / Rust 生态基础设施

允许引入，但必须满足：(a) 仅用于特定边界层，(b) 失败时零影响核心路径。

**v0.2 预计 Level 1 依赖：**

| 依赖 | 用途 | 边界层 | 替换成本 |
|------|------|--------|----------|
| `serde` / `serde_json` | FSIR JSON 序列化 | 输出层 | 低 |
| `tracing` | 可观测性 | 侧支 | 低 |
| `thiserror` / `anyhow` | 错误处理 | 全栈 | 低 |
| `nom` 或 `pest` | parser combinator / PEG | 输入层 | 中 |
| `tokio`（若需要异步） | 异步运行时 | 全栈基础 | 高 |

---

### Level 2 — 允许：零侵入 CLI wrapper

通过进程调用外部二进制，Anim 不链接任何外部 SDK。

**当前 Anim Level 2 依赖：** 无（代码零行）。

---

## 决策流程

```
1. 它能通过 CLI wrapper 模式使用吗？
   → 是：Level 2 — 零侵入允许
   → 否：进入问题 2

2. 它是 Rust 生态基础设施 / 行业通用协议实现吗？
   → 是，且仅用于边界层 → Level 1
   → 否 → 进入问题 3

3. 它会接管 Anim 的核心执行路径吗？
   → 是：Level 0 — 禁止
   → 否：回到 Level 1 判定
```

---

## 重新评估

此政策在以下时机重新评估：
- 每个 milestone 开始时：检查 Cargo.toml 新增依赖
- 任何 `cargo add` 引入不在当前清单中的 crate 时
- 引入任何与神经信号、生理数据处理相关的库时——需额外审查
